We need a "Harvard/von Neumann Jihad".

Every time we create a von Neumann system, where commands and data are mixed in the same stream, we make a system vulnerable.

Phone phreaking attacks
Buffer overrun attacks
SQL injection attacks
LLM prompt injection attacks

There are solutions for the earlier of these: keep commands and data separate. Does anyone have any solid solution to protect LLMs from prompt injection? Pre- and post- filtering of text streams just create an escalation war that cannot ever be safe.

Is there any way to transform LLMs into some kind of Harvard architecture where the machine's approach to processing the data can't be corrupted by injection of special instructions into the data? My gut feel from my understanding of how these systems work is that they are vulnerable by design -- the richness of natural language input makes security impossible. But just because I can't see a solution doesn't mean there isn't one.

#AI #LLM #Security
